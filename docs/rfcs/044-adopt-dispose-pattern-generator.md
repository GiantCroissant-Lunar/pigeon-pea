# RFC-014: Adopt DisposePattern Source Code Generator

- **Status:** Proposed
- **Author:** Planning Agent
- **Date:** 2025-11-17
- **Supersedes:** N/A
- **Related:** N/A
- **Depends On:** N/A

## Summary

Adopt the `DisposePattern` source code generator from the eco-shared repository as a standard tool for implementing `IDisposable` across the codebase. This generator eliminates boilerplate, ensures correctness, and provides consistency for resource disposal patterns.

## Motivation

### Current State

The project currently has **partial adoption** of the DisposePattern generator:

**Already Using:**

- ✅ `PigeonPea.Windows` - for `GameCanvas` disposing `SKBitmap` and `WriteableBitmap`
- ✅ `PigeonPea.Console` - (installed but may not be actively used yet)
- ✅ `PigeonPea.Shared` - (installed but may not be actively used yet)

**Not Using:**

- ❌ `PigeonPea.PluginSystem` - has manual disposal with exception swallowing
- ❌ Other projects with disposable resources

### Problems Without Generator

**Manual disposal is error-prone:**

```csharp
// Manual implementation - easy to get wrong
public class MyClass : IDisposable
{
    private Timer? _timer;
    private bool _disposed;

    public void Dispose()
    {
        if (_disposed) return;

        // Easy to forget null check
        _timer.Dispose();
        _timer = null;

        _disposed = true;
        // Forgot GC.SuppressFinalize(this)!
    }

    // No protected virtual Dispose(bool) for inheritance
    // No unmanaged resource support
}
```

**Issues:**

- ❌ Missing null checks
- ❌ Forgetting `GC.SuppressFinalize(this)`
- ❌ No support for class hierarchies
- ❌ Inconsistent patterns across codebase
- ❌ Hard to maintain when adding more disposable fields

### Goals

1. **Standardization** - One consistent disposal pattern across all projects
2. **Correctness** - Implement the full IDisposable pattern correctly
3. **Maintainability** - Easy to add/remove disposable fields
4. **Inheritance Support** - Works with class hierarchies
5. **Developer Experience** - Less boilerplate, fewer bugs

### Non-Goals

- Finalizers (prefer deterministic disposal)
- Replacing existing working disposal code (unless refactoring anyway)
- Mandating use in all classes (only where IDisposable is needed)

## What is DisposePattern Generator?

### Overview

`Plate.SCG.General.DisposePattern` is a **Roslyn source code generator** that automatically generates correct `IDisposable` implementation based on attributes.

**Source:** eco-shared repository
**Type:** Compile-time code generator (Roslyn analyzer)
**Scope:** General-purpose (any .NET project)

### How It Works

1. Mark class with `[DisposePattern]`
2. Mark disposable fields with `[ToBeDisposed]`
3. Generator creates:
   - `public void Dispose()`
   - `protected virtual void Dispose(bool disposing)`
   - `private bool _disposed` tracking field
   - Automatic null checking
   - Automatic field nulling (for non-readonly fields)
   - Four partial method hooks for custom logic

### Example Usage

**Before (Manual):**

```csharp
public class GameCanvas : Image
{
    private SKBitmap? _bitmap;
    private WriteableBitmap? _writeableBitmap;
    private bool _disposed;

    public void Dispose()
    {
        if (_disposed) return;

        _bitmap?.Dispose();
        _bitmap = null;

        _writeableBitmap?.Dispose();
        _writeableBitmap = null;

        _disposed = true;
        GC.SuppressFinalize(this);
    }
}
```

**After (With Generator):**

```csharp
using Plate.SCG.General.DisposePattern.Attributes;

[DisposePattern]
public partial class GameCanvas : Image
{
    [ToBeDisposed]
    private SKBitmap? _bitmap;

    [ToBeDisposed]
    private WriteableBitmap? _writeableBitmap;

    // Dispose() automatically generated!
    // No boilerplate needed
}
```

### Generated Code

```csharp
// Auto-generated by Plate.SCG.General.DisposePattern
partial class GameCanvas : IDisposable
{
    private bool _disposed;

    public void Dispose()
    {
        Dispose(disposing: true);
        GC.SuppressFinalize(this);
    }

    protected virtual void Dispose(bool disposing)
    {
        if (_disposed) return;

        if (disposing)
        {
            BeforeDisposeManagedResources();
            DisposeManagedResources();

            _bitmap?.Dispose();
            _bitmap = null;

            _writeableBitmap?.Dispose();
            _writeableBitmap = null;
        }

        BeforeDisposeUnmanagedResources();
        DisposeUnmanagedResources();

        _disposed = true;
    }

    // Partial method hooks for custom cleanup
    partial void BeforeDisposeManagedResources();
    partial void DisposeManagedResources();
    partial void BeforeDisposeUnmanagedResources();
    partial void DisposeUnmanagedResources();
}
```

## Architecture

### Package Structure

The generator is distributed as NuGet packages in `.local-packages/`:

```
.local-packages/
├── Plate.SCG.General.DisposePattern.0.1.0.nupkg      ← The generator
├── Plate.SCG.Shared.Attributes.0.1.0.nupkg           ← Attributes ([DisposePattern], [ToBeDisposed])
├── Plate.SCG.Shared.Abstractions.0.1.0.nupkg         ← Transitive dependency
└── Plate.Shared.Abstractions.0.1.0.nupkg             ← Transitive dependency
```

**Only directly reference:**

- `Plate.SCG.Shared.Attributes` (for attributes)
- `Plate.SCG.General.DisposePattern` (for code generation)

### Integration Pattern

**In `.csproj`:**

```xml
<ItemGroup>
  <!-- Attributes visible at runtime -->
  <PackageReference Include="Plate.SCG.Shared.Attributes" Version="0.1.0" />

  <!-- Generator runs at compile time only -->
  <PackageReference Include="Plate.SCG.General.DisposePattern" Version="0.1.0"
                    PrivateAssets="all"
                    OutputItemType="Analyzer"
                    ReferenceOutputAssembly="false" />
</ItemGroup>
```

**In code:**

```csharp
using Plate.SCG.General.DisposePattern.Attributes;

[DisposePattern]
public partial class MyClass
{
    [ToBeDisposed]
    private IDisposable? _resource;
}
```

## Detailed Design

### Phase 1: Standardize Existing Usage

**Current Projects Using Generator:**

1. **PigeonPea.Windows**
   - Already correctly configured
   - Used in `GameCanvas.cs`
   - Working example for reference

2. **PigeonPea.Console**
   - Package installed but may not be actively used
   - Audit for classes that need disposal

3. **PigeonPea.Shared**
   - Package installed but may not be actively used
   - Audit for classes that need disposal

**Action:** Document existing usage in `dotnet/source-generators/README.md`

### Phase 2: Identify Candidate Projects

**Projects That May Need Generator:**

1. **PigeonPea.PluginSystem** ⚠️ **High Priority**
   - `PluginLoader` - manages `PluginRegistry`
   - `PluginRegistry` - manages ALCs and plugin instances
   - `PluginLoadContext` - inherits from `AssemblyLoadContext`
   - `PluginHost` - may manage `IServiceProvider`
   - `MsDiAppServiceRoot` - manages `IServiceProvider`
   - `MsDiAppServiceScope` - manages `IServiceScope`

2. **Other Projects**
   - Any project with classes holding `IDisposable` fields
   - Classes managing unmanaged resources
   - Classes that need proper disposal in hierarchies

**Action:** Audit codebase for manual `IDisposable` implementations

### Phase 3: Adoption Criteria

**When to Use DisposePattern Generator:**

✅ **Use When:**

- Class has one or more `IDisposable` fields
- Class needs proper disposal pattern
- Class may be inherited (need virtual Dispose)
- Manual implementation is complex or error-prone

❌ **Don't Use When:**

- Class is simple and disposal is trivial
- Class doesn't own disposable resources
- Performance-critical path where generated code is too heavy
- Class uses custom disposal logic that doesn't fit generator model

### Phase 4: Implementation Guidelines

**Step-by-Step Process:**

1. **Add Package References**

   ```xml
   <PackageReference Include="Plate.SCG.Shared.Attributes" Version="0.1.0" />
   <PackageReference Include="Plate.SCG.General.DisposePattern" Version="0.1.0"
                     PrivateAssets="all"
                     OutputItemType="Analyzer"
                     ReferenceOutputAssembly="false" />
   ```

2. **Mark Class**

   ```csharp
   using Plate.SCG.General.DisposePattern.Attributes;

   [DisposePattern]
   public partial class MyClass  // Must be partial!
   ```

3. **Mark Fields**

   ```csharp
   [ToBeDisposed]
   private Timer? _timer;

   [ToBeDisposed]
   private HttpClient? _httpClient;
   ```

4. **Custom Cleanup (Optional)**

   ```csharp
   partial void DisposeManagedResources()
   {
       // Custom cleanup logic before automatic disposal
       _timer?.Stop();
   }
   ```

5. **Build and Verify**
   ```powershell
   dotnet build
   # Check generated code in obj/Debug/net9.0/generated/
   ```

### Phase 5: Best Practices

**DO:**

- ✅ Use for classes with multiple disposable fields
- ✅ Use for base classes that may be inherited
- ✅ Make class `partial` when using generator
- ✅ Document why fields are marked `[ToBeDisposed]`
- ✅ Test disposal in unit tests
- ✅ Verify generated code looks correct

**DON'T:**

- ❌ Mix manual `Dispose()` with generated code
- ❌ Forget to mark class as `partial`
- ❌ Dispose resources you don't own (e.g., injected singletons)
- ❌ Use for structs (not supported)
- ❌ Use `[ToBeDisposed]` on properties (fields only)

## Testing Strategy

### Unit Tests

**Test disposal behavior:**

```csharp
[Fact]
public void Dispose_CalledTwice_DoesNotThrow()
{
    // Arrange
    var obj = new MyDisposableClass();

    // Act & Assert
    obj.Dispose();
    obj.Dispose(); // Should be idempotent
}

[Fact]
public void Dispose_DisposesAllFields()
{
    // Arrange
    var mockResource1 = new Mock<IDisposable>();
    var mockResource2 = new Mock<IDisposable>();
    var obj = new MyClass(mockResource1.Object, mockResource2.Object);

    // Act
    obj.Dispose();

    // Assert
    mockResource1.Verify(x => x.Dispose(), Times.Once);
    mockResource2.Verify(x => x.Dispose(), Times.Once);
}
```

### Integration Tests

**Test in real scenarios:**

- Create and dispose objects in realistic workflows
- Verify no exceptions during disposal
- Check for resource leaks

- [ ] Fields that shouldn't be disposed are NOT marked
- [ ] Custom cleanup logic in partial methods if needed
- [ ] Unit tests verify disposal behavior
- [ ] XML documentation updated

## Migration Path

### For New Code

**Default:** Use DisposePattern generator for any new class needing `IDisposable`

### For Existing Code

**Option A: Refactor Now**

- Convert manual disposal to generator
- Test thoroughly
- Document changes

**Option B: Refactor Later**

- Leave existing code as-is
- Convert when touching code for other reasons
- Document technical debt

**Option C: No Migration**

- If disposal is simple and working, leave it
- Document why it's not using generator

## Alternatives Considered

### Alternative 1: Continue Manual Implementation

**Pros:**

- No new dependencies
- Full control over disposal logic
- No learning curve

**Cons:**

- Error-prone
- Inconsistent patterns
- More boilerplate
- Hard to maintain

**Decision:** Rejected. Benefits of generator outweigh costs.

### Alternative 2: Use Different Generator

**Pros:**

- Might have different features
- Might be more popular

**Cons:**

- Already invested in DisposePattern
- Would need to migrate existing code
- Unknown quality

**Decision:** Rejected. Current generator works well.

### Alternative 3: Build Custom Generator

**Pros:**

- Complete control
- Tailored to our needs

**Cons:**

- Significant development effort
- Maintenance burden
- Reinventing the wheel

**Decision:** Rejected. Use existing proven solution.

## Security Considerations

- Generator runs at compile time (no runtime risk)
- Generated code is visible in `obj/` for review
- No network access or external dependencies during generation
- Attributes are simple markers (no code execution)

## Performance Considerations

- Minimal impact (Roslyn generators are efficient)
- Only runs when source files change

### Runtime

- Generated code is optimal
- Same performance as hand-written disposal
- No reflection or dynamic code

## Appendix C: Troubleshooting

### "Type is not partial"

**Problem:** Class not marked `partial`
**Solution:** Add `partial` keyword to class declaration

### "Attribute not found"

**Problem:** Missing package reference
**Solution:** Add `Plate.SCG.Shared.Attributes` package

### "Generated code not appearing"

**Problem:** Generator not running
**Solution:**

1. Clean and rebuild
2. Check package has `OutputItemType="Analyzer"`
3. Restart IDE

### "Field not disposed"

**Problem:** Field missing `[ToBeDisposed]`
**Solution:** Add attribute to field
