# Astro Starlight Docs Site

This guide explains how the Astro **Starlight** documentation site in this
repository is structured, how it integrates with the existing `docs/`
corpus and `docs/index/registry.json`, and how to run and maintain it.

## Overview

The docs site lives under:

- `docs-site/` — Astro project using the Starlight theme
- `docs-site/src/content/docs/` — Starlight content collection
- `docs-site/src/components/ExternalDoc.astro` — Renders real markdown
  docs from `docs/`
- `scripts/docs_mgmt/generate_starlight_wrappers.py` — Generates
  Starlight wrapper pages from the documentation registry

The **source of truth** for documentation remains the markdown files
under `docs/` with YAML front-matter validated by
`scripts/docs_mgmt/validate-docs.py`. The Starlight site is a
presentation layer on top of that corpus.

## How canonical docs are surfaced

1. `scripts/docs_mgmt/validate-docs.py` scans `docs/`, validates
   front-matter, and generates `docs/index/registry.json`.
2. `scripts/docs_mgmt/generate_starlight_wrappers.py` reads the
   registry and creates one **wrapper MDX file** for each
   **canonical** document:
   - Output directory: `docs-site/src/content/docs/<doc_type>/`
   - File name: `<doc_id>.mdx` (for example
     `docs-site/src/content/docs/rfc/RFC-00012.mdx`)
   - Each wrapper contains front-matter copied from the registry
     (title, summary, etc.) and an `<ExternalDoc>` component that
     renders the real markdown from `docs/`.

3. Starlight auto-discovers these wrapper files and uses them to build
   the sidebar and routes. When you navigate to a page in the
   Starlight site, you are still reading the underlying markdown from
   `docs/`.

## ExternalDoc component

File: `docs-site/src/components/ExternalDoc.astro`

Responsibilities:

- Look up a document by `doc_id` in `docs/index/registry.json` using the
  helper functions in `docs-site/src/lib/registry.js`.
- Load the markdown file from the `docs/` tree.
- Strip YAML front-matter so the content can be rendered as markdown.
- Render the body using Astro's `<Markdown>` component, along with a
  simple header (title, doc_id, type, status, summary).

Wrapper pages import and use this component like:

```mdx
import ExternalDoc from '../../../components/ExternalDoc.astro';

<ExternalDoc docId="RFC-00012" />
```

## Sidebar and section ordering

The Starlight configuration in `docs-site/astro.config.mjs` defines an
explicit sidebar order based on `doc_type`:

1. RFCs (`rfc/`)
2. Guides (`guide/`)
3. Architecture Decision Records (`adr/`)
4. Plans (`plan/`)
5. Specifications (`spec/`)
6. Reference (`reference/`)

Each entry is configured as an **autogenerated group** that pulls in all
wrapper pages from the corresponding directory:

```js
sidebar: [
  { label: 'RFCs', autogenerate: { directory: 'rfc' } },
  { label: 'Guides', autogenerate: { directory: 'guide' } },
  {
    label: 'Architecture Decision Records',
    autogenerate: { directory: 'adr' },
  },
  { label: 'Plans', autogenerate: { directory: 'plan' } },
  { label: 'Specifications', autogenerate: { directory: 'spec' } },
  { label: 'Reference', autogenerate: { directory: 'reference' } },
];
```

The order of this array controls the section ordering in the sidebar.
Files inside each directory are ordered by filename, which generally
corresponds to `doc_id` ordering.

## Running the docs site locally

From the repository root:

1. Ensure Python dependencies for docs tooling are installed
   (see `requirements/dev.txt`).
2. Regenerate the documentation registry and Starlight wrappers:

   ```bash
   # Regenerate docs/index/registry.json (optional but recommended)
   python scripts/docs_mgmt/validate-docs.py

   # Generate Starlight wrapper pages for canonical docs
   cd docs-site
   npm run docs:sync
   ```

3. Install Node dependencies and start the dev server:

   ```bash
   cd docs-site
   npm install
   npm run dev
   ```

4. Open the URL printed by Astro (typically
   `http://localhost:4321/`).

## Building for production

To build the static docs site:

```bash
cd docs-site
npm run docs:sync   # Ensure wrappers are up to date
npm run build
```

The static site will be written to `docs-site/dist/` and can be served
by any static file host.

## When to regenerate wrappers

Run `npm run docs:sync` (after updating the registry) when:

- New canonical docs are added under `docs/`.
- Existing canonical docs change their title, summary, or status and
  you want the Starlight front-matter to reflect those updates.
- Doc types (`doc_type`) change and you want wrapper files to move to a
  different section in the sidebar.

Non-canonical docs are intentionally **excluded** from the Starlight
site. They remain available in the raw `docs/` tree and in any
non-Starlight indexes you generate.

## Notes and limitations

- The Starlight site currently mirrors high-level structure by
  `doc_type` only. If you need finer-grained grouping (for example,
  grouping by tag or topic), you can extend the generator or add
  additional sidebar configuration later.
- The registry and validation tooling remain the primary authority for
  documentation metadata. The Starlight wrappers are generated files
  and should not be edited manually.
